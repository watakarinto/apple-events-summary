# 製品セクションの執筆ルール（apple-event-writer 用）

読者が**何が変わったのかをすぐ追える**記事にすることが最優先です。

## 手順

1. 字幕ファイル（英語、1行1字幕）を Read で全文読む
2. 下の構成でセクションを書き、出力ファイルに Write する
3. 最後の返答は次の3行だけにする（本文は返さない）

```
価格: {製品・モデルごとの価格。字幕に無ければ「言及なし」}
発売日: {予約・発売日。字幕に無ければ「言及なし」}
要点: {デバイスごとの主な変更点を1行で。複数デバイスなら「AirPods 4: …／AirPods Max: …」}
```

## 構成（厳守）

```markdown
## {製品名}

### ここが変わった

- **{変更点の名前}**：{何がどう変わったかを1行で。数値があれば必ず入れる}
- （重要な順に 5〜10 項目）

### 詳細

#### {機能・トピック}

{説明は短い段落か箇条書き。1段落は3文まで。仕様や数値の比較は表にする}

### 価格・発売日

| モデル | 価格 | 発売日 |
|--------|------|--------|
```

- チャプター内に複数のデバイスがある場合（例：AirPods 4 / AirPods Max / AirPods Pro 2）
  - 「ここが変わった」の中でデバイスごとに太字ラベル（`**AirPods 4**`）を立て、空行をはさんでそれぞれの箇条書きを書く
  - 「詳細」ではデバイスごとに `####` 見出しを立てる
- 箇条書きは「何が・どう変わったか」が1行で分かる書き方にする（例：「**ディスプレイ**：表示領域が最大30%拡大（Series 4 比）」）
- 新機能は「新機能」、既存機能の改善は「向上」「拡大」など、変化の種類が分かる言葉を使う
- 見出しは `#####` 以下を使わない
- frontmatter・他製品・まとめ・`---` 区切り・画像行は書かない（画像は組み立て時に自動で挿入される）

## 書かないもの（厳守）

- 登壇者・担当者の名前、誰が話したか、誰が紹介したか
- ユーザーの体験談や事例紹介、映像・会場の演出
- 宣伝文句・キャッチコピー・主観的な評価（「最高の」「驚くほど」など）
- 字幕に無い情報（推測や一般知識による補足）

## 内容の方針

- 読者は **Apple 好き・デベロッパ**。字幕で言及された機能・数値・対応状況・API 名は詳細ですべて拾う
- 書くのは事実（機能・仕様・数値・対応モデル・提供時期）だけにする
- 数値の比較は、字幕に根拠がある場合だけ書く
- 字幕の文をそのまま訳して並べない。要約した独自の文章にする（著作権への配慮）
